# rustpoc — empirical C-vs-Rust benchmarks on the real kernel hot paths

Proof-of-concept for `docs/RUST_VS_C_KERNEL.md` §3. Three kernel hot paths are
benchmarked as shipped C (the actual `c/src` sources, production native flags)
against faithful safe-Rust ports, over identical workloads generated by the
real engine. **Every port is verified by checksum: the Rust implementation
must reproduce the C output bit-for-bit before its timing counts.**

## What is measured

| bench | C code under test | Rust port | workload |
|---|---|---|---|
| `legal` | `c/src/legal.c` `calculate_legal_moves` (per-move enumeration, runs on every action + every bot decision) | `rs/src/bin/bench_legal.rs`, two variants: *faithful* (same bool tables) and *idiomatic* (u64/u16 bitmasks, same emitted order) | 20,000 decision states from 240 full games (2–8 players), dumped by `gen_states.c` driving the real engine |
| `playout` | `c/src/cordite_sim.c` `cd_sim_playout` + the handwritten rollout policy (the Monte-Carlo hot loop of the shipped cordite/octogen bots) | `rs/src/bin/bench_playout.rs` — full SimState bitboard engine incl. the game LCG | 600 of those states, played to completion with per-playout seeds |
| `wire` | `c/src/msg_wire.c` `msg_decode`/`msg_encode` (the iMessage FMSG envelope — the hostile-bytes parser) | `rs/src/bin/bench_wire.rs` | 2,000 envelopes produced by the real `msg_encode` (1 in 8 corrupted) |

The playout port includes the engine LCG and all `double` math; its checksums
match the `-ffast-math -flto` clang build, the gcc build, and Rust exactly —
i.e. bit-exact cross-language behavior is achievable even for the float-bearing
rollout policy, which is what makes differential C↔Rust migration testing
credible.

## Reproduce

```bash
make gen          # play 240 games through the real kernel, dump workloads
make bench-c      # clang -O3 -ffast-math -flto (production flags)
make bench-c-gcc  # same flags, gcc — calibrates compiler-vs-compiler variance
make bench-rs     # cargo --release (opt-level=3, fat LTO, 1 CGU, panic=abort)
```

Checksums printed by all implementations for a given (bench, reps) pair must
be identical; timings are wall-clock best-of-N inside each process, and the
report takes best-of-5 process invocations.

## Results (this container: 4-core x86-64, Linux 6.18, clang 18 / gcc 13 / rustc 1.94)

Best-of-5 invocations, best-rep within each:

| bench | c-clang | c-gcc | rust (safe, faithful) | rust idiomatic |
|---|---|---|---|---|
| legal, ns/call | 417 | **384** | 477 (+14% vs clang) | 433 (+4%) |
| playout, µs/playout | **1.41** | 1.62 | 1.59 (+13% vs clang, −2% vs gcc) | — |
| wire, ns/envelope | 734 | 746 | **700** (−5% vs clang) | — |

Struct sizes: `SimState` 328 B (C) vs 320 B (Rust, field reordering);
`MsgEnvelope` 616 vs 608; `LegalMoves` identical. Peak RSS is
workload-dominated and equal within noise on all three.

Read: the deltas are inside the gcc↔clang band (legal ±8%, playout ±15%) and
the direction flips per workload. Language choice does not decide performance
here; both sit on the same LLVM/GCC codegen quality, and the C is already
well-optimized. The full interpretation lives in `docs/RUST_VS_C_KERNEL.md`.
