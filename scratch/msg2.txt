winprob: the strip is a file, with the reader beside the writer

The strip was a pass with a TSV dump hanging off its CLI. It is now what the
analyser is: an entry that returns packed bytes, a reader beside the writer,
and a command line that is only a presentation layer over the reader.

  c/src/winprob.{h,c}   winprob_packed + winprob_read_header/_step
  c/src/main_winprob.c  --bin writes the bytes; the summary, the sparklines
                        and the --tsv dump are all read back OUT of them, so
                        the text cannot drift from the file

The wire is fixed stride and both strides are in the header, so a consumer
seeks to step i rather than walking to it: little-endian, probabilities
x10000, finish positions x1000, nothing floating and no JSON near it. Per
seat, per step, in both views: the fool probability, the mean finish position
and the hand size; per step the move that led there, so a label needs nothing
else. An 8-seat 146-step game is 13,422 bytes.

c/tools/winprob/winprob_bin.py is the same reader in Python and is what the
plotter now takes. winprob.c is deliberately NOT in CORE_SRC: nothing on a
phone or in a wasm module should carry its bytes.

Two things are now checked rather than trusted. The writer and the strides
the reader seeks by are two statements of one layout, so they are held
against each other at the one moment the answer is known - which is how the
first version's off-by-two stride was caught instead of shipping a file whose
every step was misaligned. And a step's truth probabilities must still sum to
one.

c/tools/winprob/checks.sh holds the rest against a real game: one thread
against eight, the same run twice, a different seed, a truncated file. Each
was mutation-checked. The first attempt at the thread mutation proved
nothing - seeding game_rng per worker changed no byte, because the truth view
of a deterministic engine never reads that stream - so the mutation moved to
random_strategy_set_seed, which a playout does consume, and the check went
red as it should.

cli_util.h grows has_flag. get_arg only ever matched "--key=value", so every
bare --quiet in the tree read as absent; main_analyse.c had the same bug and
is fixed with it.

The document says v6 is the decoder family and 10 is the version byte codes
are cut under today, because reading "a v6 code" and then seeing v10 on the
wire is a trap the format's own doc warns about and this one did not.
