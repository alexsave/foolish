# words.txt - the names one side of the tree may not say about another.
#
# Two gates read this file:
#   foolish/e2e/validation/shared_is_shared_validation.test.ts: nothing under
#     shared/ hits a [products] pattern;
#   c_base/core/test/unit_name_gate.c (c_base/docs/PLATFORM.md 8.4): c_base's
#     core hits no pattern of any list, a provider no [products] or [domain]
#     pattern, foolish/server/src no [providers] pattern, but for the lines of
#     allow.txt beside this file.
#
# The format: a line "[<list>]" starts a list; every other line that is not
# blank or a "#" comment is one pattern, written as a JavaScript regular
# expression literal, /<source>/ or /<source>/i (case-insensitive), so the
# TypeScript gate hands it to RegExp as it is. The C gate matches the subset
# the patterns use: literal characters, "\" before a punctuation character
# (a literal), "\b" (a word boundary), "\w" (a word character), and "?" and
# "*" after any of those. One difference, on purpose: in the C gate "_" is
# not a word character, because C joins words with it, so /\bbots?\b/i
# finds cb_rows_bots_replace.

[products]

# ("Pick 'Em Up", "Pick Em Up", "pickemup").
