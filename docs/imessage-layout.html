Foolish · design study nº4 · Messages

Durak in an iMessage bubble

Mockups for the Messages extension specified in docs/IMESSAGE_GAME_DESIGN.md: the in-thread game bubble, the compact drawer, the expanded table, the group lobby, the finished-game card, and the /m/ web fallback. The expanded surfaces share the iOS app's world — felt, bone cards, fern backs, one red — with the web's wool weave tinting the felt and a wood rail on the extension chrome. The bubble snapshot is the small-size problem the watch already solved, so it borrows the watch's glyph-card language (docs/watchos-layout.html §8). Build instructions live in docs/IMESSAGE_IMPLEMENTATION_HANDOFF.md.

Scale

1 · The five facts that shape every frame

FactDesign consequence
Extensions can't send — insert only stages into the input field (IMESSAGE_GAME_DESIGN.md §17.1) The staged state is a first-class screen (IM4): amber "staged — hit send" banner, Send-move disabled until resolved
One bubble per game via MSSession; older bubbles collapse to summaryText (§11.3) Summaries are written as a readable transcript ("Sveta covered 7♠ and attacked 9♣") — IM1 shows them inline
The bubble image is visible to everyone, incl. notifications (§10) The snapshot renders only public state: card backs, battles, counts, trump — never a hand
Durak is multi-actor — several seats may act at once (§5.1) No "your turn" framing anywhere; Send-move enables on ≥1 applied action with the "others may be playing too" hint (IM3)
Mac/Android/SMS recipients see a raw URL (§17.6) The /m/ page (IM7) is a real product surface, not an error page

2 · The frames

IM1–IM4 are one 2-player game seen from Boris's phone; IM5 is a 4-player group lobby; IM6 ends the game; IM7 is what a Mac/Android friend sees. v1 caps the UI at 4 players (protocol runs 2–8) — seat chips here relax to the 84 pt size, so Messages never needs the SE study's 7-chip compression.

3 · Bubble snapshot spec 300×195 pt @3x

Rendered with UIGraphicsImageRenderer into MSMessageTemplateLayout.image. Zones, at the 270 pt rendered width the bubble actually gets:

ZoneContentLanguage
Seat line (top, centered)per-seat hand counts; defender count inside the gold shield outline; green = said good; brass = the viewer is never marked (public image!)watch SeatStrip, unchanged semantics

Template fields (§11.3 recipe): layout.image = this snapshot · layout.caption = localized "Your move" / "Game on" · layout.trailingCaption = "Turn n" · message.summaryText = the transcript line. The app icon slot in the caption bar is drawn by Messages, not by us.

4 · Fern, wood, wool — where each lives

  • Fern (the brand): card backs everywhere — bubble snapshot, drawer row thumbnails, expanded table, app icon. Same seeded IFS port the app uses (IOS_APP_DESIGN.md §5.3); the extension reuses FoolishKit's cached CGImage, no second implementation.
  • Wool (the web's table): a low-alpha weave tint over the felt on the two big surfaces (bubble snapshot, expanded table). Kept at ≤6% alpha so the Gosizdat felt stays dominant and text contrast is untouched.
  • Wood (the web's chrome): one 5 pt grain rail under the extension's top bar and above the drawer — a nod to the site's wooden buttons without importing skeuomorphic buttons wholesale.
  • Everything else is the app's token set verbatim — this keeps FoolishKit's DesignSystem the single source for both targets (§9.2: extension links FoolishKit).
