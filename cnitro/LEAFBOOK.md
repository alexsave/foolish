# LEAFBOOK — a precomputed canonical endgame oracle

The S3 spend of `docs/L1_SPEND_PLAN.md`: bake the exhaustively-solved value of
every small round-boundary endgame into a read-only book, and probe it inside
the bitboard solver *before* the transposition table. A book hit terminates the
whole subtree with a proven value — no search, no TT traffic, no budget.

It is the first "spend the free L1" candidate to beat the control (R2): at pc2
it makes hexogen **11% faster** (30.08 → 26.72 ms/dec) at neutral-to-slightly-
better strength, because it attacks a *different* axis than more search worlds
(the saturated one — see the world-budget knee in the Ordnance Chart).

## What it stores

A round-boundary 2-player deck-empty endgame — `num_battles==0`, nobody said
good, deck empty, two players IN — is fully specified by
**(attacker hand, defender hand, trump suit)**. Its game value is invariant
under the RANKSYM orbit: a global monotone rank-compaction (absolute ranks are
irrelevant once missing cards are gone; only within-suit order and cross-suit
equality matter) and a relabeling of the three non-trump suits (durak treats
them symmetrically). `src/leafbook.h` is the single canonical form used by both
the offline builder and the in-engine probe, so a built key and a probed key are
bit-identical by construction. The value byte is
`outcome{loss,draw,win}<<4 | distance` from the attacker-to-move's perspective.

## Reach K — the feasibility gate (`make leafbook-gate`)

Distinct canonical forms grow ~10× per card: K=4 → 1,883 (1.8 KiB), K=5 →
19,715 (19.3 KiB), K=6 → 205,853 (201 KiB, over budget). **Shipped K=4** as a
key-sorted `(uint64 key, uint8 value)` array with binary search — exact, needs
no perfect hash. K=5 fits L1 only via a 1-byte/entry index store
(minimal-perfect-hash by enumeration rank); it is the natural next step and
reaches bigger, budget-binding subtrees.

## Correctness (`make leafbook-verify`) — must be 100%

Two independent gates, both required to pass exactly:
1. **Offline V-book** — 10⁶ random concrete positions: book-through-
   canonicalization vs a direct exact solve. Proves the orbit invariance the
   book rests on (outcome AND mate distance). 100.000% / 0 mismatches.
2. **In-engine probe** — 2×10⁶ engine solves (both attacker/defender roles):
   book-ON (probe fires at the root) vs book-OFF (full search). Proves the
   attacker/defender identification, the attacker→me perspective flip, and the
   depth rebase. 0 mismatches.

The book is proven-exact, so enabling it can only ever change play by resolving
a line the budget-limited search would have *aborted* — never by returning a
wrong value.

## Wiring

- `src/leafbook.h` — canonicalization (header-only; also linked by the tools).
- `src/leafbook_data.h` — GENERATED by `make leafbook`; committed.
- `cordite_sim.c` — the probe in `sim_solve_rec` behind `-DCD_LEAFBOOK`, before
  the TT probe; runtime-gated by `cd_sim_set_leafbook` (thread-local).
- `hexogen_strategy.c` — turns the book on for the span of a hexogen decision.
  octogen and every shipped family never set the gate → **byte-identical**
  (R1, verified by V0 + bot_parity). Compiled into NATIVE builds only; the wasm
  module (no hexogen) carries no book.
- `tools/leafbook/{enumerate,build_book,verify_book}.c` — the gate, builder, and
  value-safety verifier.

## Regenerating after a solver change

`make leafbook` (rebuild the book) then `make leafbook-verify` (must stay 100%).
`LEAFBOOK_K=5 make leafbook` changes reach (needs the index store to fit L1).
